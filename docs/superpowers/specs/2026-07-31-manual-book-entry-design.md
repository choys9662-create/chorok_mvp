# 책 검색·바코드·직접 입력 추가 흐름 설계

## 목표

사용자는 서재에 책을 추가할 때 검색을 기본 수단으로 사용한다. ISBN 바코드 스캔은 검색만큼 자주 쓰일 수 있는 빠른 대안으로 명확히 노출하고, 직접 입력은 검색과 바코드 조회로도 책을 찾지 못했을 때만 사용하는 최후의 수단으로 둔다.

책을 직접 입력할 때 기록하는 서지 정보는 제목, 작가, 총 페이지 수로 제한한다.

## 정보 위계와 진입점

### 1. 검색

- 서재의 `책 추가` 동작은 지금처럼 검색 화면으로 이동한다.
- 검색창은 화면에서 가장 넓은 상단 요소로 유지한다.
- 검색 결과에서 책을 선택하고 서재 상태를 정하는 기존 흐름을 유지한다.

### 2. 바코드 스캔

- 검색창 오른쪽의 48pt ISBN 스캔 버튼을 항상 노출한다.
- 버튼은 아이콘과 브랜드 강조색을 사용해 직접 입력보다 눈에 띄게 한다.
- 검색어 입력 여부와 관계없이 스캔 화면에 바로 진입할 수 있다.

### 3. 직접 입력

- 검색 화면의 상단이나 초기 빈 화면에는 직접 입력을 노출하지 않는다.
- 검색 결과가 없거나 검색 요청이 실패했을 때 `그래도 책을 찾을 수 없나요? 직접 입력` 텍스트 링크를 표시한다.
- ISBN 조회 결과가 없거나 조회 오류가 발생했을 때 스캐너의 상태 카드에 `직접 입력` 링크를 표시한다.
- 직접 입력은 카드형 주요 CTA가 아닌 보조 텍스트 액션으로 표현한다.

## 직접 입력 화면

직접 입력은 별도 화면으로 제공한다. 화면에는 다음 입력만 둔다.

- 제목: 필수, 앞뒤 공백 제거
- 작가: 필수, 앞뒤 공백 제거
- 페이지 수: 필수, 1 이상의 정수

입력값이 유효해지기 전에는 저장 버튼을 비활성화한다. 숫자 키보드를 사용하고 페이지 수에는 숫자 이외의 입력을 허용하지 않는다. 필드 아래에는 누락 또는 잘못된 값을 짧게 안내한다.

저장을 누르면 기존 서재 추가 상태 시트를 재사용해 `읽는 중`, `읽고 싶어요`, `읽었어요` 중 하나를 선택한다. 사용자가 상태 선택을 취소하면 입력 화면과 작성한 값은 유지한다.

## 데이터 흐름

1. 검색 실패 화면 또는 바코드 실패 상태에서 직접 입력 화면으로 이동한다.
2. 사용자가 세 필드를 입력하고 저장을 누른다.
3. 상태 선택 시트에서 독서 상태를 선택한다.
4. 앱은 `manual_<microsecondsSinceEpoch>` 형식의 로컬 고유 ID를 생성한다.
5. `Book`을 다음 값으로 생성한다.
   - `title`: 정리된 제목
   - `author`: 정리된 작가
   - `totalPages`: 입력한 페이지 수
   - `status`: 선택한 상태
   - `isbn`, `coverUrl`, `genre`, `description`: `null`
   - `currentPage`: `0`
6. 기존 `libraryProvider`의 `addBook`을 사용해 상태를 즉시 반영하고 기존 Supabase 저장 경로를 그대로 사용한다.
7. 직접 입력 화면은 추가 성공 결과를 호출 화면에 반환한다.
8. 검색 화면에서 진입했다면 검색 화면은 유지하고 완료 안내를 표시한다. 스캐너에서 진입했다면 스캐너를 닫고 검색 화면으로 돌아가 완료 안내를 표시한다.

ISBN이 없는 직접 입력 책은 `global_books`에 등록하지 않는다. 사용자별 `books` 저장에는 기존 열인 제목, 작가, 총 페이지 수를 사용하므로 데이터베이스 스키마 변경은 필요하지 않다.

## 중복 처리

저장 전에 현재 서재에서 앞뒤 공백을 제거한 제목과 작가가 모두 같은 책을 확인한다. 같은 책이 있으면 새로 추가하지 않고 `이미 서재에 있는 책이에요`라고 안내하며 입력 화면을 유지한다.

대소문자가 있는 외국어 제목과 작가는 비교할 때 소문자로 정규화한다. 페이지 수가 다르더라도 제목과 작가가 같으면 중복으로 본다.

## 구성요소 변경

- `search_screen.dart`
  - 바코드 버튼의 현재 위치를 유지하고 시각적 강조를 보장한다.
  - 검색 결과 없음 및 검색 오류 상태에 직접 입력 콜백과 보조 링크를 추가한다.
- `barcode_scanner_screen.dart`
  - 조회 실패 여부를 별도 상태로 관리한다.
  - 실패 상태 카드에 직접 입력 콜백을 추가한다.
- `manual_book_entry_screen.dart`
  - 제목, 작가, 페이지 수 입력과 검증, 상태 선택, 저장을 담당한다.
- `add_to_library_sheet.dart`
  - 검색 결과 모델에 종속되지 않고 제목만으로 상태 시트를 열 수 있는 내부 진입점을 추가한다.
  - 기존 검색·탐색·상세·바코드 호출 방식은 유지한다.
- `app_constants.dart`, `app_router.dart`
  - 직접 입력 화면 경로를 추가한다.

새로운 공용 위젯은 만들지 않는다. 화면은 `AppTheme` 토큰과 기존 `ChorokCard`, 시트 구성요소를 조합한다.

## 오류 처리

- 검색 결과 없음 또는 검색 요청 실패: 직접 입력 링크 표시
- 바코드에서 ISBN 형식은 맞지만 결과 없음: 재스캔 안내와 직접 입력 링크 표시
- 바코드 조회 통신 오류: 재시도 안내와 직접 입력 링크 표시
- 필드 누락 또는 잘못된 페이지 수: 해당 필드 오류 표시, 저장하지 않음
- 중복 책: 안내만 표시하고 화면과 입력값 유지
- 저장 호출: 기존 `LibraryNotifier.addBook`의 즉시 상태 반영과 백그라운드 저장 동작을 유지

## 테스트

### 검색 화면 위젯 테스트

- 검색창과 바코드 버튼은 초기 화면에서 보인다.
- 직접 입력 링크는 초기 화면에서 보이지 않는다.
- 검색 결과가 없거나 검색 요청이 실패했을 때 직접 입력 링크가 보인다.
- 직접 입력 링크를 누르면 직접 입력 경로로 이동한다.

### 바코드 화면 위젯 테스트

- 일반 스캔 대기 상태에는 직접 입력 링크가 보이지 않는다.
- ISBN 조회 결과 없음 또는 오류 상태에는 직접 입력 링크가 보인다.
- 링크를 누르면 직접 입력 경로로 이동한다.

### 직접 입력 화면 위젯 테스트

- 제목, 작가, 페이지 수 외의 서지 입력 필드가 없다.
- 필수값과 페이지 수를 검증한다.
- 상태 선택 취소 시 입력값을 유지한다.
- 유효한 입력과 상태 선택으로 생성된 책이 서재에 추가된다.
- 제목과 작가가 같은 기존 책은 중복 추가되지 않는다.

## 완료 기준

- 사용자는 서재의 책 추가에서 검색을 가장 먼저 마주한다.
- 바코드 스캔은 검색창 옆에서 항상 직접 접근할 수 있고 직접 입력보다 강하게 보인다.
- 직접 입력은 검색 실패 또는 바코드 조회 실패 뒤에만 발견된다.
- 직접 입력 책은 제목, 작가, 페이지 수와 선택한 독서 상태만으로 기존 서재 저장 경로에 정상 저장된다.
- 관련 위젯 테스트와 대상 파일 정적 분석이 통과한다.
